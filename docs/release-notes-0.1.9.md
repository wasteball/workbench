# Workbench 0.1.9

这一版修复旧版上传网关的配置兼容问题，并把“该填哪一组信息”直接写进配置页。

## 下载与安装

普通用户不需要安装开发工具，也不需要运行任何命令。

当前版本是 Chrome 商店上线前的公开预览版：

1. 下载 `workbench-browser-extension-0.1.9-chrome.zip`。
2. 右键 ZIP 文件并选择“全部解压”。
3. 在 Chrome 地址栏打开 `chrome://extensions`。
4. 开启“开发者模式”。
5. 点击“加载已解压的扩展程序”，选择刚刚解压的文件夹。

这是预览期的临时安装方式。Chrome 商店版上线后，将改为在商店中直接安装和自动更新。

## 本次修复

- 参考旧版 `md-html-workspace.html` 使用上传地址、Bucket 和用户标识时，应选择“单位或服务提供的连接”。
- 旧网关的公开读取参数恢复为 `1/0`，不再发送不兼容的 `true/false`。
- 个人阿里云直连与旧网关在配置页中明确分开，避免把上传 API 地址误填到阿里云 Endpoint。
- 上传失败会显示 HTTP 状态和服务端返回的错误原因；连接失败会提示检查插件来源的 CORS 设置。
- 存储配置指南补充两种连接的最小填写方式和排查顺序。

## 验证情况

- 新增旧网关参数回归测试，确认 CDN 使用 `true/false`、公开读取使用 `1/0`。
- 19 个测试文件共 52 项单元测试全部通过，STS 测试通过。
- ESLint、TypeScript、文档链接、发布内容扫描和 Chrome 正式构建均通过。

实际上传仍依赖用户自己的上传服务或阿里云账号。本项目不会内置、读取或代替用户验证真实 AccessKey、Bucket、用户标识和服务端 CORS 配置。

## 数据与权限

- 本次更新没有新增浏览器权限，也没有改变本地文件和用户偏好的处理方式。
- 本地文件默认不会上传；只有主动上传或在线分享时，内容才会发送到用户选择的存储服务。
- 不包含 Workbench 自有账号、广告、遥测、内置存储地址或预置密钥。

## 已知限制

- 当前仍需手动加载预览版，正式面向普通用户的 Chrome 商店版本尚未上线。
- 上传网关必须支持旧版 multipart 协议，并允许当前 Chrome 扩展来源跨域访问。
- 阿里云 OSS 必须配置匹配的 RAM 权限和 CORS 规则；仅填写 AccessKey 不能替代这两项设置。

# Workbench 0.1.13

这一版集中修复文件库的下载与分享体验：上传后的文件可以直接下载，保存时使用原文件名；分享内容默认可以直接粘贴到聊天工具；不常用的链接下载入口默认收起，让文件库更清爽。

## 下载与安装

普通用户不需要安装开发工具，也不需要运行任何命令。

首次安装：

1. 下载 `workbench-browser-extension-0.1.13-chrome.zip`。
2. 右键 ZIP 文件并选择“全部解压”。
3. 在 Chrome 地址栏打开 `chrome://extensions`。
4. 开启“开发者模式”。
5. 点击“加载已解压的扩展程序”，选择刚刚解压的文件夹。

## 从旧预览版升级

不要先卸载旧版。卸载扩展会让 Chrome 清除当前插件的偏好、草稿和文件库记录。

1. 建议先在“设置 → 权限与隐私”中选择“备份偏好与文件库”。
2. 下载并解压新版，把新版文件覆盖到原来加载 Workbench 的文件夹。
3. 打开 `chrome://extensions`，在 Workbench 卡片上点击“重新加载”。

使用原文件夹直接更新时，主题、阅读宽度、草稿、分类和文件库记录都会保留。

## 本次更新

- **上传文件可以正常下载**：文件库和上传完成区都能直接保存文件，不再被额外的网站授权步骤拦住。
- **保留原文件名**：即使在文件库中修改了显示名称，下载时仍使用上传文件原来的名称，中文名称和扩展名不会丢失。
- **分享内容可以直接粘贴**：分享按钮默认复制“文件名、换行、链接”；需要其他格式时，仍可在设置中选择 Markdown 链接、单行文字或仅链接。
- **链接下载默认收起**：只有需要通过对象存储地址下载时再展开，减少普通用户初次进入文件库时的操作负担。
- **对象存储错误继续拦截**：失效地址返回的 OSS XML 错误不会被当作 Markdown 或其他文件保存。

## 数据与权限

- 本次更新没有新增浏览器权限。
- 本次更新没有修改存储配置、文档、草稿、分类或文件库的数据结构。
- 同一插件直接更新会保留本地数据；不要为了升级而先卸载旧版。
- 本地文件仍默认只在浏览器中处理，只有用户主动上传或在线分享时才会连接所选存储服务。

## 已知限制

- 当前仍需手动加载预览版，正式面向普通用户的 Chrome 商店版本尚未上线。
- 上传和私有文件下载依赖用户自己的 API 服务或阿里云 OSS；服务端仍需正确配置访问权限和 CORS。
- 不允许跨域读取的下载地址会交给 Chrome 打开，由目标服务决定直接下载还是显示文件。
- 文件库是当前浏览器的上传记录，不是 OSS Bucket 的完整文件浏览器。
- 卸载扩展仍会让 Chrome 清除插件本地数据；必须卸载时，请先备份偏好与文件库。

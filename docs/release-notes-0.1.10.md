# Workbench 0.1.10

这一版把“文件与分享”补成了可以日常使用的文件库：既能一次上传文件或整个文件夹，也能搜索、分类和批量整理上传记录；通过对象存储链接下载 Markdown 等文件时，会保留原文件名和原始内容。

## 下载与安装

普通用户不需要安装开发工具，也不需要运行任何命令。

当前版本是 Chrome 商店上线前的公开预览版：

1. 下载 `workbench-browser-extension-0.1.10-chrome.zip`。
2. 右键 ZIP 文件并选择“全部解压”。
3. 在 Chrome 地址栏打开 `chrome://extensions`。
4. 开启“开发者模式”。
5. 点击“加载已解压的扩展程序”，选择刚刚解压的文件夹。

这是预览期的临时安装方式。Chrome 商店版上线后，将改为在商店中直接安装和自动更新。

## 本次更新

- **上传整个文件夹**：可以选择或拖入文件夹，Workbench 会递归上传其中的文件，保留相对路径，并按顶层文件夹自动归类。
- **统一文件库**：上传成功的文件都进入当前浏览器的文件库，可搜索、查看、分享、复制链接、修改显示名称、下载、移动分类或移除记录。
- **分类和类型筛选**：可以新增、重命名和删除分类；文件会按图片、文档、表格、演示、视频、音频、压缩包、代码等类型自动归类。分类或类型很多时仍保持一行，可横向滚动查看。
- **批量整理**：支持多选、全选当前结果、批量分享、复制链接、下载、移动分类和移除记录，也可以一次清空全部文件库记录。
- **直接下载对象存储文件**：粘贴 HTTP(S) 地址即可下载，优先保留服务端提供的原文件名、中文名称和扩展名。
- **长列表更流畅**：文件库首次显示 120 条记录，其余内容按需加载；长列表提供回到顶部和回到底部操作。

## 下载问题修复

- Markdown、图片和其他文件会按原始字节保存，不再把 Markdown 错误下载成 XML。
- 当阿里云 OSS 返回权限、签名或对象不存在等 XML 错误时，Workbench 会显示错误原因，不会把错误页面当成目标文件保存。
- 当前浏览器上传过的私有 OSS 文件如果链接过期，下载时会尝试重新生成有效的限时链接。

## 文件与云端的边界

- 文件库保存的是当前 Chrome 中的上传记录，方便日常查找和整理。
- 修改显示名称、移动分类、移除记录或“全部清空”，只改变浏览器里的记录，不会重命名或删除 OSS 中的真实文件。
- Workbench 不读取整个 Bucket，也不要求远端列出、重命名或删除权限。
- 本地打开、编辑、预览和导出仍然不需要配置云存储。只有主动上传或在线分享时，内容才会发送到用户选择的存储服务。

## 验证情况

- 21 个测试文件共 62 项单元测试全部通过，STS 测试通过。
- ESLint、TypeScript、文档链接、发布内容扫描和 Chrome 正式构建均通过。
- 在独立 Chrome 环境中用 135 条文件记录验证搜索、筛选、横向滚动、分批显示和窄屏布局，页面无横向溢出。
- 使用嵌套文件夹完成 3 个真实文件的递归上传验证，中文名称、相对路径和顶层分类均被保留。
- 使用中文 Markdown 文件验证下载文件名和内容不变，并验证 OSS XML 错误不会被保存成文件。

## 数据与权限

- 移除 `downloads` 浏览器权限；上传文件和通过链接下载时，使用 Chrome 自身的文件选择与保存能力。
- 本地文件默认不会上传；只有用户主动上传或在线分享时才会联网。
- 不包含 Workbench 自有账号、广告、遥测、内置存储地址或预置密钥。

## 已知限制

- 当前仍需手动加载预览版，正式面向普通用户的 Chrome 商店版本尚未上线。
- 上传和私有文件下载依赖用户自己的上传服务或阿里云 OSS；服务端仍需正确配置访问权限和 CORS。
- 文件库只包含当前浏览器成功上传或分享后留下的记录，不是 OSS Bucket 的完整文件浏览器。
- 批量下载会由 Chrome 逐个保存文件；浏览器可能询问是否允许一次下载多个文件。

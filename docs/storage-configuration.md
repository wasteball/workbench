# 存储配置指南

Workbench 不自带云存储。上传和在线分享需要用户连接自己的上传网关或阿里云 OSS；不配置时，本地 Markdown 功能照常使用。

## 选择哪一种连接

| 场景 | 建议方式 |
| --- | --- |
| 已经有兼容接口，并由管理员提供 API 地址、Bucket 和用户标识 | 上传网关 |
| 个人管理阿里云 OSS，能够创建独立 RAM 用户 | 阿里云 OSS AccessKey |
| 有自己的服务端，希望浏览器只拿短期凭证 | 阿里云 OSS STS |

所有连接都在“设置 → 存储连接”管理。文件与分享、Markdown 在线分享和 Popup 不再各自保存一份配置。

## 上传网关

### 用户需要填写

- 连接名称：只用于当前浏览器中辨认连接。
- API 地址：接收上传请求的完整 HTTP(S) 地址。
- Bucket：由网关管理员提供。
- 用户标识：由网关管理员提供。
- CDN、公开读取：按网关实际契约选择。
- 自定义请求头：只有管理员明确要求时才填写。

保存后，“测试连接”只能检查字段和网站权限。当前协议没有无副作用的健康检查，因此不会试传文件，也不会把“配置格式有效”说成“写入权限已验证”。

### 当前请求契约

Workbench 发送 `multipart/form-data` POST，请求字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file` | 文件 | 用户选择的文件或 Markdown 导出结果 |
| `bucket` | 字符串 | 配置中的 Bucket |
| `cdn` | `"true"` / `"false"` | CDN 开关 |
| `publicRead` | `"true"` / `"false"` | 用户选择的读取方式 |
| `userCode` | 字符串 | 配置中的用户标识 |

成功响应必须是 JSON，并在 `data.downUrl` 或顶层 `downUrl` 返回有效的 HTTP(S) 链接。

发布前仍需由网关维护者确认：

- 认证方式和必需请求头；
- 非 2xx 错误响应结构；
- 单文件和请求大小限制；
- 同名文件覆盖规则；
- 返回链接是公开、需登录还是会过期；
- 是否存在无副作用的测试接口；
- CORS 允许的扩展来源和请求头。

在这些信息确认并完成真实上传测试前，该连接器只能视为兼容实现，不能标记为生产验证通过。

## 阿里云 OSS AccessKey

### 先在阿里云侧准备

1. 创建独立 RAM 用户，不使用主账号 AccessKey。
2. 把权限限制到实际使用的 Bucket 和对象前缀。
3. 只授予需要的动作，例如上传、列出、读取、删除或修改 ACL。
4. 为 Bucket 配置适合扩展来源的 CORS。具体规则以阿里云 OSS 当前文档和真实浏览器请求为准。
5. 创建 AccessKey，并只在 Workbench 设置页中填写。

### Workbench 字段

| 字段 | 示例含义 |
| --- | --- |
| 地域 | OSS SDK 使用的地域，例如 `oss-cn-hangzhou` |
| Endpoint | 可选；使用特殊 OSS Endpoint 时填写，必须是 HTTPS 主机地址 |
| Bucket | 目标存储空间名称 |
| 对象前缀 | 可选；把 Workbench 文件限制在某个目录样式前缀下 |
| AccessKey ID / Secret | 独立 RAM 用户的凭据 |
| 默认访问方式 | 私有对象生成限时签名链接；公开对象生成对象 URL |
| 签名有效期 | 60 至 86400 秒 |

“仅本次使用”时，Secret 只进入扩展会话存储或运行内存；关闭浏览器会话后需要重新填写。“在此浏览器记住”会把 Secret 写入扩展本地存储，不会同步或导出。

浏览器扩展存储不是系统钥匙串。如果设备会被其他人使用，或需要更强的凭据保护，请使用 STS。

### 最小权限思路

权限应与界面实际开放能力一致：

- 只上传：对象前缀下的写入和分片上传。
- 查看云端文件：增加 Bucket 列表权限，并用前缀条件限制。
- 私有分享：增加读取/签名所需权限。
- 公开分享：增加设置对象 ACL 的权限。
- 删除：只在确实需要时增加删除权限。
- 重命名：OSS 实际执行“复制新对象后删除旧对象”，需要读取、写入和删除。

Workbench 会根据测试结果和 STS 声明隐藏不支持的远端动作，但 RAM Policy 仍是最终安全边界。

## 阿里云 OSS STS

STS 模式由用户自己的 HTTPS 服务签发短期凭证。Workbench 向该服务发送：

```json
{
  "region": "oss-cn-hangzhou",
  "bucket": "example-bucket",
  "prefix": "workbench/"
}
```

服务必须验证调用者身份，并自行固定或校验允许的 Bucket、前缀和权限，不能直接信任请求内容。响应格式和参考服务见[STS 集成指南](sts-integration.md)。

STS 凭证剩余不足 5 分钟时不会开始新上传。刷新失败只会暂停新的远端任务，不影响本地文档和导出。

## 网站权限与 CORS

Workbench 在首次访问每个网关、STS 或 OSS 域名时请求对应网站权限。用户拒绝后，本地功能仍可使用。

网站权限允许扩展发起请求，但服务端仍需正确配置 CORS、认证和 RAM Policy。排查顺序：

1. 确认设置中的地域、Endpoint 和 Bucket 没有混用。
2. 确认浏览器已授予目标域名权限。
3. 在服务端日志或 OSS 控制台确认请求是否到达。
4. 检查 CORS 是否允许扩展实际发送的 Origin、方法和请求头。
5. 检查 RAM Policy 是否覆盖对象前缀和具体动作。

不要通过关闭浏览器安全策略或使用公共跨域代理解决生产问题。

## 配置迁移与删除

- 配置导出始终清除 AccessKey、用户标识和请求头值。
- 导入后需要重新填写这些敏感字段。
- 删除连接会清除该连接已保存的凭据，但不会删除远端对象。
- “清除本地数据”会删除设置、草稿和分享记录；已经上传的文件仍留在相应服务中。

# 存储配置指南

Workbench 不自带云存储。上传和在线分享需要用户选择 API 方式或阿里云 OSS；不配置时，本地 Markdown 功能照常使用。

## 选择哪一种连接

| 场景 | 建议方式 |
| --- | --- |
| 已经有兼容接口，并由管理员提供 API 地址、Bucket 和用户标识 | API 方式 |
| 个人管理阿里云 OSS，能够创建独立 RAM 用户 | 阿里云 OSS AccessKey |
| 有自己的服务端，希望浏览器只拿短期凭证 | 阿里云 OSS STS |

连接只在“设置 → 云端分享”管理，并通过“API 方式 / 阿里云 OSS”单选切换。每种方式只保留一份配置；文件与分享、Markdown 在线分享和浏览器工具栏入口不再各自保存配置。

## 文件库和链接下载

- 每次上传成功后，Workbench 都会把文件名、原相对路径、分类、大小、链接和上传时间保存到当前浏览器的文件库。
- 文件库支持打开、分享、复制链接、修改显示名称、下载、移动分类、移除记录和批量操作。
- 修改显示名称、移动分类、移除记录或“全部清空”只整理当前浏览器中的记录，不会修改或删除对象存储里的文件。
- 文件夹上传会递归读取文件，并按顶层文件夹自动建立本地分类。
- “通过链接下载”可粘贴 HTTP(S) 对象存储地址；Workbench 会优先恢复服务端提供的原文件名和中文名称。若 OSS 返回的是 XML 错误信息，不会把它误存成 Markdown 文件；若地址不允许跨域读取，会改为在新标签打开。

Workbench 不提供 Bucket 全量浏览入口。文件库只管理由当前浏览器成功上传或分享后留下的记录，避免用户误以为清理本地列表等同于删除云端数据。

### 先判断你拿到的是什么信息

- 如果你拿到的是“上传地址、Bucket、用户标识”，选择 **API 方式**。这就是旧版 `md-html-workspace.html` 使用的方式。
- 如果你拿到的是阿里云控制台中的“地域、Bucket、AccessKey ID、AccessKey Secret”，选择 **阿里云 OSS**。
- 不要把上传网关的 API 地址填到阿里云的 Endpoint；也不要把 `oss-cn-…` 地域代码填到上传网关的上传地址。

## API 方式

### 用户需要填写

- API 地址：接收上传请求的完整 HTTP(S) 地址。
- Bucket：由网关管理员提供。
- 用户标识：由网关管理员提供。
- CDN、公开读取：按网关实际契约选择。
- 自定义请求头：只有管理员明确要求时才填写。

最小可用填写方式是：API 上传地址填完整的上传接口（通常以 `/upload` 结尾）、Bucket 填空间名称、用户标识填管理员分配的值；CDN 和公开读取先按关闭处理，只有服务提供者明确要求时再打开。

保存后，“测试连接”只能检查字段和网站权限。当前协议没有无副作用的健康检查，因此不会试传文件，也不会把“配置格式有效”说成“写入权限已验证”。

### 当前请求契约

Workbench 发送 `multipart/form-data` POST，请求字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `file` | 文件 | 用户选择的文件或 Markdown 导出结果 |
| `bucket` | 字符串 | 配置中的 Bucket |
| `cdn` | `"true"` / `"false"` | CDN 开关；旧版网关使用这两个文字值 |
| `publicRead` | `"1"` / `"0"` | 用户选择的读取方式；`1` 为公开读取，`0` 为私有读取 |
| `userCode` | 字符串 | 配置中的用户标识 |

成功响应必须是 JSON，并在 `data.downUrl` 或顶层 `downUrl` 返回有效的 HTTP(S) 链接。

发布前仍需由网关维护者确认：

- 认证方式和必需请求头；
- 非 2xx 错误响应结构；
- 单文件和请求大小限制；
- 同名文件覆盖规则；
- 返回链接是公开、需登录还是会过期；
- 是否存在无副作用的测试接口；
- CORS 允许的扩展来源和请求头。

在这些信息确认并完成真实上传测试前，该连接器只能视为兼容实现，不能标记为生产验证通过。旧版 `md-html-workspace.html` 使用的就是这一种网关协议；不要把网关 API 地址填到“阿里云 OSS”的 Endpoint 里。

## 阿里云 OSS AccessKey

### 先在阿里云侧准备

1. 创建独立 RAM 用户，不使用主账号 AccessKey。
2. 把权限限制到实际使用的 Bucket 和对象前缀。
3. 只授予需要的动作，例如上传、列出、读取、删除或修改 ACL。
4. 为 Bucket 配置适合扩展来源的 CORS。具体规则以阿里云 OSS 当前文档和真实浏览器请求为准。
5. 创建 AccessKey，并只在 Workbench 设置页中填写。

### Workbench 字段

| 字段 | 示例含义 |
| --- | --- |
| 地域 | OSS SDK 使用的地域，例如 `oss-cn-hangzhou` |
| Endpoint | 可选；使用特殊 OSS Endpoint 时填写，必须是 HTTPS 主机地址 |
| Bucket | 目标存储空间名称 |
| 对象前缀 | 可选；把 Workbench 文件限制在某个目录样式前缀下 |
| AccessKey ID / Secret | 独立 RAM 用户的凭据 |
| 默认访问方式 | 私有对象生成限时签名链接；公开对象生成对象 URL |
| 签名有效期 | 60 至 86400 秒 |

最小可用填写方式是：地域填阿里云控制台显示的代码（例如 `oss-cn-hangzhou`）、Bucket 只填空间名称、Endpoint 先留空、填写独立 RAM 用户的 AccessKey ID 和 Secret。若你使用的是旧版上传地址，这一整组字段不适用。

“仅本次使用”时，Secret 只进入扩展会话存储或运行内存；关闭浏览器会话后需要重新填写。“在此浏览器记住”会把 Secret 写入扩展本地存储，不会同步或导出。

浏览器扩展存储不是系统钥匙串。如果设备会被其他人使用，或需要更强的凭据保护，请使用 STS。

### 最小权限思路

权限应与界面实际开放能力一致：

- 只上传：对象前缀下的写入和分片上传。
- 私有分享：增加生成限时签名链接和读取对象所需权限。
- 公开分享：增加设置对象 ACL 的权限。

当前文件库不执行远端列出、重命名或删除，因此不应仅为 Workbench 额外授予这些权限。RAM Policy 始终是最终安全边界。

## 阿里云 OSS STS

STS 模式由用户自己的 HTTPS 服务签发短期凭证。Workbench 向该服务发送：

```json
{
  "region": "oss-cn-hangzhou",
  "bucket": "example-bucket",
  "prefix": "workbench/"
}
```

服务必须验证调用者身份，并自行固定或校验允许的 Bucket、前缀和权限，不能直接信任请求内容。响应格式和参考服务见[STS 集成指南](sts-integration.md)。

STS 凭证剩余不足 5 分钟时不会开始新上传。刷新失败只会暂停新的远端任务，不影响本地文档和导出。

## 网站权限与 CORS

Workbench 在首次连接网关、STS 或 OSS 时请求对应网站权限。用户拒绝后，本地功能仍可使用。“通过链接下载”优先按服务端 CORS 规则直接保存，不额外要求网站权限；地址不允许跨域读取时，会把原地址交给浏览器处理。旧版 HTML 通常来自 `file://` 或普通网页，而 Chrome 插件来自 `chrome-extension://<扩展 ID>`；因此服务端还必须允许插件来源，旧版能上传不代表插件也能直接上传。

网站权限允许扩展发起请求，但服务端仍需正确配置 CORS、认证和 RAM Policy。排查顺序：

1. 确认设置中的地域、Endpoint 和 Bucket 没有混用。
2. 确认浏览器已授予目标域名权限。
3. 在服务端日志或 OSS 控制台确认请求是否到达。
4. 检查 CORS 是否允许扩展实际发送的 Origin（通常是 `chrome-extension://<扩展 ID>`）、POST 方法和 `Content-Type` 等请求头；阿里云 OSS 还要允许当前扩展来源的 PUT/POST/GET/HEAD 请求。
5. 检查 RAM Policy 是否覆盖对象前缀和具体动作。

不要通过关闭浏览器安全策略或使用公共跨域代理解决生产问题。

## 配置迁移与删除

- 配置导出始终清除 AccessKey、用户标识和请求头值。
- 导入后需要重新填写这些敏感字段。
- “清空此方式”会清除该方式已保存的配置和凭据，但不会删除远端对象。
- “备份偏好与文件库”会保存分类和上传记录，但会剔除 AccessKey、用户标识和请求头密钥；恢复后需要重新填写这些敏感信息。
- “清除本地数据”会删除设置、草稿、文件库分类和分享记录；已经上传的文件仍留在相应服务中。
